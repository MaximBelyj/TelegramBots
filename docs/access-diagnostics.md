# Доступ к источникам, версия v0.1.1

Проверялись общедоступные поисковые страницы: DMR на маркетплейсах, LM358 в каталогах радиодеталей, гражданские трансиверы на QRZ.ru. Оценивалось наличие распознаваемой выдачи или явного ответа «ничего не найдено», а не только HTTP 200. Политика среды при проверке: unrestricted; это не доказывает работоспособность каждой внешней прокси-маршрутизации.

| Источник | Наблюдение | Действие |
| --- | --- | --- |
| Avito | CONNECT-запрос отклонён прокси; ответ сайта не получен | Ручная ссылка. Для восстановления требуется разобраться с маршрутом/доступом у оператора среды; новый GitHub-токен не нужен |
| Ozon | Нестабильно: пустая оболочка, переадресация в категорию; при последней проверке получена распознаваемая выдача | Обычная cookie-сессия, проверки сохранения поискового запроса. Успешный запрос допускает автоматический поиск; отказ выключает его |
| Wildberries | HTTP 498 | Ручная ссылка, длительная пауза. Для устойчивого доступа нужен поддерживаемый интерфейс/разрешение площадки |
| Яндекс Маркет | В разные моменты CAPTCHA и реальная выдача | При CAPTCHA запросы прекращаются; успешная проверка допускает автоматический поиск |
| Чип и Дип | HTTP 403, ранее DDoS-Guard | Ручная ссылка; согласованный доступ или предоставляемая площадкой выгрузка вместо повторов |
| Платан | Реальная выдача LM358, 8 прошедших фильтр карточек при контрольном поиске | Автоматический поиск с интервалом не менее 10 секунд после завершения предыдущего запроса |
| Промэлектроника | Реальная выдача LM358; встречается HTTP 403 | Автоматический поиск до отказа, минимум 15 секунд между запросами, затем пауза и ручной режим |
| QRZ.ru | Реальная выдача трансиверов и явный нулевой результат LM358 | Автоматический поиск, реклама вне выдачи исключена, минимум 15 секунд между запросами |
| RadioKot | HTTP 403 либо HTTP 200 без распознаваемой выдачи | Ручная ссылка; адаптер реальных тем пока не подтверждён |

Количество товаров зависит от запроса и момента проверки. Успешная проверка не гарантирует последующие ответы и не означает продажу/наличие товара. Назначение сайта в режиме «ручная ссылка» — открыть его самостоятельно; бот не использует браузер пользователя и не копирует его cookies.

## Очередь и паузы

`SearchEngine` используется и ручным, и периодическим поиском. Для каждого сайта одна очередь и одна сессия; cookies находятся только в оперативной памяти. Очередь одного сайта не блокирует остальные. Базовый интервал 15 секунд, для Платана 10. Интервалы отсчитываются после завершения предыдущего запроса; обычная цепочка перенаправлений выполняется в рамках этого запроса. Отменённая задача освобождает очередь.

403/498, CAPTCHA/вход и отказ прокси: минимум 6 часов без новых запросов, затем только явная проверка доступности. Неподдерживаемая разметка/перенаправление: минимум 1 час и явная проверка. 429: минимум 30 минут; учитывается Retry-After (секунды или HTTP-дата). Сетевые ошибки: минимум 5 минут. При повторных отказах пауза растёт экспоненциально до суток; более длинный Retry-After соблюдается полностью. Для временных сетевых ошибок и 429 после паузы разрешён один пробный автоматический запрос.

Режимы и сроки записываются в `data/source_health.json` (`DMR_HEALTH_PATH`), поэтому перезапуск не сбрасывает запрет на повторы. Там нет названий искомых изделий, товарных результатов, тел запросов, cookie, ключей и параметров URL. Диагностическая цепочка содержит только HTTP-код, имя хоста и путь. Успешная проверка старше суток становится неизвестным статусом до новой проверки. Не удаляйте файл ради снятия паузы.

В меню «Площадки» показаны статусы и кнопка «Проверить доступность». Она делает по одному контрольному запросу на сайт, кроме источников, чей срок паузы ещё не истёк. Новые непроверенные источники не включаются в автоматические обращения молча. Все сайты сохраняются в том же меню, без отдельной кнопки основного меню.

Для диагностики из корня репозитория:

```bash
.venv/bin/python -m dmr_bot.search_engine
```

## Варианты получения устойчивого доступа

Если площадка предлагает официальный поиск/API, фид или разрешённый экспорт, нужен конкретный интерфейс с правами именно на требуемые товары. Seller API нередко предоставляет только данные собственного кабинета, а не поиск по всей площадке; добавление такого API без проверки области доступа не решает задачу. Интеграции с API в этой версии не заявлены и не реализованы.

Другой вариант — согласовать доступ с владельцем сайта или получать объявления через его штатные сохранённые поиски/уведомления. Для постоянной работы процесса нужен отдельный хостинг, но перенос на другой сервер сам по себе не гарантирует доступ. CAPTCHA, ротация адресов для обхода блокировки, подмена браузерных отпечатков и повтор запросов вопреки ограничениям не используются.
