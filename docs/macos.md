# Проверка доступа на macOS

Эта проверка сравнивает доступ к публичным поисковым страницам из домашней сети и облачной среды. Тот факт, что сайт открыт в Safari/Chrome, не означает, что автоматический HTTP-клиент получит те же данные. Помощник не использует cookies браузера, не решает CAPTCHA и не запускает второй экземпляр Telegram-бота.

## Первый запуск

Откройте приложение «Терминал» (Cmd+Пробел, введите «Терминал»). Вставляйте команды по одной:

```bash
git clone https://github.com/MaximBelyj/TelegramBots.git TelegramBots-mac-check
cd TelegramBots-mac-check
bash scripts/macos-check.sh
```

Если папка уже существует, не удаляйте её: перейдите в существующую копию и обновите через `git pull --ff-only`, если в ней нет собственных изменений, либо используйте новое имя папки при клонировании.

Если macOS предлагает установить инструменты разработчика для команды Git, выполните штатную установку и повторите команду клонирования. Если Git не устанавливается, можно скачать ZIP версии v0.1.2 со страницы репозитория, распаковать и перейти в полученную папку через Терминал.

Нужен Python 3.11 или новее; рекомендуются 3.12/3.13 с https://www.python.org/downloads/macos/. Для уже установленного Homebrew подойдёт `brew install python@3.12`. Скрипт сам выбирает доступный Python, создаёт `.venv` в папке проекта и ставит зафиксированные зависимости. Системный Python и глобальные пакеты он не изменяет. Для существующей, но неподходящей `.venv` помощник останавливается, не удаляя её.

## Результат

Терминал покажет состояние каждого из девяти источников. Отчёт сохраняется в `data/macos-access-report.txt`. Его можно прислать для сравнения с облачной диагностикой. В отчёте только статусы, причины ошибок и HTTP-цепочки с хостом/путём, без токенов, cookies и поисковых параметров.

Локальные сроки пауз находятся в `data/source_health.macos.json`. Это отдельная проверка другой машины/сети; последующие запуски на Mac сохраняют эти паузы. Не удаляйте файл ради повторения заблокированных запросов. Папка `data/` исключена из Git.

Ключ Telegram для проверки **не нужен**. Работающий облачный бот продолжает работу; локальный помощник не читает и не подтверждает Telegram-обновления, не меняет список изделий и не сохраняет найденные товары.

## Как интерпретировать

- Если тот же источник работает на Mac, но не в облаке, результат указывает на влияние маршрута, адреса, прокси или условий окружения. Это не доказывает одну конкретную причину.
- Если сайт открывается в браузере, а помощник получает 403/CAPTCHA/пустую оболочку, требуется разобраться с разрешённым способом загрузки данных; смена хостинга сама по себе может не помочь.
- Настройки VPN/прокси браузера могут отличаться от Терминала. Помощник использует стандартные сетевые настройки HTTP-клиента; значения переменных окружения не выводятся.

Перенос самого бота на Mac — отдельный шаг после сравнения. До него нельзя запускать второй polling-процесс с тем же Telegram-токеном. Круглосуточная работа на Mac потребует включённого компьютера, сети и настройки поведения при сне.

## Браузерная проверка RadioKot, Ozon и Wildberries (v0.1.4)

В уже клонированной папке выполните:

```bash
git pull --ff-only
bash scripts/macos-check.sh browser
```

Помощник установит дополнительный Playwright и Chromium в `.venv` и `data/playwright-browsers`. Загрузка браузера требует нескольких сотен мегабайт на диске. Используются обычные TLS-проверки загрузчика, без отключения проверки сертификатов. Зависимости браузерной диагностики отделены в `requirements-browser.lock`; серверу Telegram-бота они не нужны.

Откроется видимое окно Chromium с отдельным временным профилем. По очереди открываются RadioKot (LM358), Ozon (DMR), Wildberries (DMR). Для каждого сайта выполняется одна навигация, затем ожидание 8 секунд для обычного JavaScript. Посмотрите страницу и нажмите Enter **в Терминале** для перехода к следующему сайту. При запросе CAPTCHA или входа не выполняйте их, просто нажмите Enter. Не переходите по ссылкам вручную и не вводите личные данные.

Не используются профиль Safari/Chrome, сохранённые пароли, личные cookies, подмена отпечатков, сторонние прокси или средства обхода защиты. Это диагностика обычной браузерной загрузки, не подтверждение разрешения сайта на дальнейший автоматический сбор.

Отчёт: `data/macos-browser-report.json`. Можно прислать именно его. HTML, скриншоты, HAR, заголовки запросов, значения полей форм, cookies и пароли не сохраняются. В отчёте есть только тип результата, HTTP-коды/хосты/пути, число распознанных карточек/тем и структура форм (имена полей без значений). Для RadioKot это поможет отличить настоящую выдачу от страницы формы поиска и проверить правильность параметров адаптера.

Классификации:

| Значение | Смысл |
| --- | --- |
| `results` | После загрузки DOM наш обработчик распознал карточки/темы, исходный запрос сохранён |
| `explicit_empty` | Распознан явный ответ об отсутствии результатов |
| `challenge`, `login` | Требуется CAPTCHA/проверка или авторизация; диагностика их не проходит |
| `http_403`, `http_429`, `http_498` | Браузерный документ тоже получил отказ |
| `search_form_instead_of_results` | У RadioKot открыта форма поиска вместо выдачи |
| `search_context_lost` | Переход на страницу без исходного запроса; не считается успехом |
| `unknown_layout` | Получен DOM, но адаптер не распознаёт его; это не доказательство блокировки |
| `navigation_incomplete`, `diagnostic_error` | Проверка не завершилась; успешный доступ не подтверждён |

По окончании временный профиль закрывается. Облачный бот продолжает работу: токен Telegram не нужен, обновления Telegram не читаются. Отчёт браузера не сбрасывает сроки защитных пауз и не включает сайты в автопоиск автоматически. Даже если браузер показывает товары, потребуется отдельно проверить применимость разрешённого сценария в автоматическом поиске.

В облачной среде форма поиска RadioKot ответила HTTP 403, поэтому исправление её запроса/разметки до получения локальных структурных данных не заявлено. Локальная проверка загрузчика в Linux выполнена на искусственной странице с JavaScript и перехваченными запросами; это не проверка реальных сайтов из сети Mac. Видимый режим на macOS предстоит выполнить пользователю.
